# FinTrack 1.2.0 — Android build 7

Canonical server: https://fintrack.eucodes.tech

The native app now uses Outfit, the web palette and borderless surfaces across Home, Plans, Activity, Reports, Settings, Account, authentication and editors. Startup and initialization show the app icon. Profile editing supports name, email, phone and a square 384px JPEG photo limited to 128KB, using the authenticated Cloudinary proxy.

Navigation pushes destinations above Home, keeps screen state, ignores repeated destinations and pops sheets before screens. Home clears the stack. Notification routes retain Home underneath.

Category budgets include plans. The effective budget is the higher of the manual limit and planned occurrences; actual spending includes linked payments. Additional category reserves exclude outstanding commitments to prevent double reservation. Use plan total removes the manual override.

Weekly/custom-day schedules and recharge validity are supported. Recharge validity restarts on the actual payment date; only one overdue recharge is retained. Historical payments/skips are preserved. Calendar-month forecasts use exact scheduled dates alongside payday-cycle totals. Category colors are persisted and used as accents.

Finance capability 2 is required after release activation. Rejected older clients retain their local pending edits. Updating the native server origin requires sign-in again without removing the account database. No database migration is required.

Validation:
- Web lint, TypeScript, production build and 70 finance/API/database tests passed.
- Flutter analysis and 49 unit/widget tests passed, including populated screens at 360/390/430/768px with 130% text and a keyboard-visible short form.
- Android emulator UI tests cover screen navigation, preserved search, linked payment totals, account editing, dark mode and photo compression. Notification initialization passed.
- An isolated production account verified two-client sync, a 28-day recharge payment, account PATCH, compressed Cloudinary photo upload and removal. The disposable test account was removed afterward.
- Web screens at 360/390/430/768/1440px had no horizontal overflow.
- APK version/build and matching prior signing certificate verified. Private production backup saved before publishing.

Limitations: Android checks ran on a Pixel emulator, not a physical phone. A physical-device check of OEM back gestures, gallery permissions and background reminder delivery remains advisable. Resend settings exist in production but are hidden; live feedback email delivery was not exercised by sending a test message. The APK retains the existing private-test signing key.

Install the APK over the existing app; do not uninstall or clear storage. Sign in once on the new origin, then sync. Refresh the web app to load capability 2. No ledger conversion or manual database migration is needed.

Before/after screenshots are saved locally in artifacts/ui/native-before-home.png and artifacts/ui/native-after-home.png. All synthetic ledger data is confined to test fixtures and integration tests.
